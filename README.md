# 杀戮尖塔2：盟约

0.6.19 适配 Steam public-beta v0.114.0（a7b9a9c0），无需其他模组前置。

用卡牌组成盟约，积累本局层数，获得全局效果和逐卡特性。以同时启用六角色卡池的完整卡池玩法为标准。设置中的“开启全卡池”默认开启，对下一局生效。角色流派盟约不限定使用者的角色。

## 盟约规则

- 718 张原版卡牌使用逐卡特性。运行时直接读取编译后的效果数据。
- 多数盟约数值使用50层一档的整数刻度，部分概率随层数连续增长。盟约层数和东尼的连续触发计数均以999为上限。可以开启“显示公式”查看计算过程，卡牌图鉴和盟约图鉴始终显示卡牌特性和公式。
- 层数持续整局，战斗中生成的牌也可以增加层数。各盟约的能量收益独立结算。
- 战斗中计入手牌、抽牌堆、弃牌堆、消耗牌堆和正在结算的牌。消耗牌堆中的状态牌和衍生牌除外。胜利结算及局外按牌组计数。同一盟约内，同名牌只计入一次，升级状态可以决定该牌计入哪些盟约。
- 能力牌结算离场后，其已打出的持续特性继续生效。仪式保留本场战斗达到的最高阶段。调和在战斗开始时根据牌组确定，激活时给达到 I 级张数的其他盟约各加 1 张。
- 绝技计入升级牌及能升级现有牌的牌。调和只计入熵，先古计入所有先古牌。奇遇计入正常卡池以外的非临时牌，包括富足、异鸟扑击和异鸟猛击等任务产物，并排除能通过其他牌定向生成的战斗衍生牌。
- 独行没有层数，计入所有不同名的牌。牌组中有重名的非诅咒牌时，独行在本场战斗中失效。
- 瓦库、东尼都是5张激活的副盟约，没有普通叠层档位。瓦库要求第一回合首张打出的牌位于手牌最左侧，接管后实际支付资源自动出牌，每回合最多13张。
- 东尼由精选的防御收益牌组成，可在盟约图鉴查看。回合结束时格挡恰为16则获得额外回合，连续触发时累计减少开场能量。
- 每局从当前角色卡池与无色卡池随机选出20至30张命运牌，另随机选出2张普通牌和3张罕见牌作为神喻。开启全卡池时使用六个角色卡池。名单互不重复，候选牌升级前后的可见徽记都少于5枚，且稀有度须为非基础。
- 命运在3张和6张时激活。神喻只在战斗开始时判定，集齐5张即可从抽牌堆选出等量卡牌代替起手抽牌。
- 万象按永久牌组的颜色数激活，无色算一种颜色。5色时，每种颜色首次打出都可减免另一种颜色的手牌的能量消耗。7色时，触发完全部颜色后即可开始下一轮。
- 每场开场附加“鏖战”状态，统计敌人回合。普通、精英、首领的宽限期分别为20、30、50个敌人回合。超过宽限期的一半后，本场战斗停止增加盟约层数。超过宽限期后，每个敌人回合开始时受到5、10、15……点伤害。额外玩家回合不推进计数。

## 界面

顶部统计栏固定居中。超过十个盟约时默认显示前十个，点击右侧箭头可展开并左右滚动。进入商店自动折叠，进入战斗默认显示统计栏。遗物栏默认只显示一行，展开后每行约五个遗物并向下排列。

悬停盟约可查看效果，单击可跳到对应的盟约图鉴分页。命运使用金色徽记，神喻使用带淡金外晕的红色徽记。两者在卡面置顶，激活后在顶部统计栏优先显示神喻、再显示命运。

在卡牌奖励和商店悬停卡牌时，统计栏按取得该牌后的状态排序，并放大有变化的盟约。移开鼠标即恢复。

盟约外环按卡牌张数分段，未激活时显示距离第一阶段的进度。未激活且为零层的盟约按距离第一阶段还差的张数升序排列。内外圆之间保持透明。I／II位于扇环平均半径处，周围使用透明镂空。卡牌徽记使用同款圆形样式并标出盟约名称。

“显示卡牌特性”使用原版勾选框。开启时局外常驻显示；战斗中平时只显示与该牌直接有关的特性，悬停时显示完整特性。关闭时只在悬停时显示。提示框位于卡牌上方；查看卡牌详情时移至两侧关键词区域；出牌飞出时立即隐藏。

战斗中，正在生效的延时或跨牌特性使用各自的原版状态图标和提示。局外特性显示在左栏，包括奖励页。卡牌描述沿用原版说明控件、能量图标与黄色关键字。设置第一页底部的「杀戮尖塔2：盟约」入口提供全卡池、敌人强化和隐藏商人手选项。

## 构建与验证

```powershell
dotnet build Covenant.csproj -c Release -p:GameData="<游戏目录>/data_sts2_windows_x86_64"
python -X utf8 checks/revision_compiler_test.py
dotnet run --project checks/RevisionCoreCheck/RevisionCoreCheck.csproj -c Release
```

修改逐卡效果时，使用 `tools/export_vanilla_cards.ps1` 导出所安装版本的原版卡牌。编译器默认从 `../proj/114` 读取本地原版源码，并使用导出的 v0.114.0 卡牌数据。可分别用 `COVENANT_NATIVE_SOURCE` 和 `COVENANT_NATIVE_EXPORT` 指定路径。

```powershell
python -X utf8 tools/compile_revision05.py
./tools/run_revision_smoke.ps1 -Run 1 -Focus staged-descriptions
python -X utf8 tools/compile_revision05.py --apply
./tools/run_revision_smoke.ps1 -Run 2 -Focus descriptions
python -X utf8 tools/verify_revision_catalog.py
```

修改提案后，首次验证使用 `-Focus staged-descriptions` 检查待接入的数据。接入后使用 `-Focus descriptions` 检查实际编入模组的数据。当前检查位于 `checks/`。

`tools/run_revision_smoke.ps1`提供按改动范围执行的检查；`-Focus release`集中执行发行前机制、界面、奖励和存档写入，`-Focus resume`在新进程继续原生存档。测试固定使用窗口和加速模式，只在独立副本及独立用户目录运行。`tools/run_revision_climb.ps1`执行一次原生辅助三幕路线。

打包使用 `./tools/run_revision_smoke.ps1 -Run 3 -Focus compatibility` 输出的日志，运行 `./tools/package.ps1 -CompatibilityLog audits/0.5/revision-console-03.log`。打包脚本核对验证日志和 DLL 的 SHA-256。兼容性检查覆盖单机加载、718 张卡牌的特性表达式及本次变更的重点触发。

## 安装

关闭游戏，将发行包中的`Covenant`文件夹放入游戏目录的`mods`目录，在游戏模组菜单中启用后重启。建议开始新的一局。发行包不包含测试探针、游戏文件或其他模组。旧存档的层数会保留档位与档内进度进行换算，超过999的部分截断；不重复迁移。
